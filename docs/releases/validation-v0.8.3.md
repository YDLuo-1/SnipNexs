# SnipNexs 0.8.3 本地修复交付

日期：2026-10-30。基于 `2a555a1c163860a237167cb9b236547aaecb066f` 的当前开发树；未提交、打标签或发布 GitHub Release。

运行 `dist/SnipNexs-0.8.3-win64/bin/SnipNexs.exe`，或完整解压同名 ZIP 后运行。包含三套离线翻译模型，不要只复制 EXE。ZIP 共 1,274,075,638 字节，SHA-256：

`5784e6bb8d891f81f6e611e52d72f501133f1ba1b421f487f441cc21af4daf20`

## 修复范围

1. 高质量引擎 prefill 按最多 512 token 分批，并按实际 prompt token 数分段、预留输出空间。原 600 字/563 token 输入不再崩溃；超出输出上限明确失败。
2. 先验证新部署和 ZIP，再处理旧目录。历史、模型先保留并迁移，其他新增/修改文件留在 `user-data/<旧部署名>`。同名冲突、运行中实例、目录链接和越界路径阻止危险清理；保留旧 ZIP。
3. OCR 保留 Latin 词边界；中文/日文识别器遇到 Latin 内容可用已安装的英语能力重试。翻译方向按当前编辑文本推断，可明确选择中文/英文；英语和中文 GDI 测试画面通过。
4. OPUS 英译中加入原始目标语言 token `>>cmn_Hans<<`。复验还发现并补齐输入 `</s>`，修复重复输出。两者分别处理，见 [CTranslate2 特殊 token 说明](https://opennmt.net/CTranslate2/guides/transformers.html#special-tokens-in-translation)。
5. 普通/对照模式共用句子与 240 token 分块，关闭底层静默截断。长行末尾的 123456789 与 987654321 分别保留。极端重复词若达到输出限制，必须明确失败且不返回半截译文。
6. 安装器改为程序、插件、许可文件白名单；历史、设置和运行时模型不进入安装器。离线 ZIP 模型另按固定哈希打包。
7. 两种引擎支持取消；关闭窗口只取消自己的任务；服务销毁先取消再等待。取消后的同一 session 能继续翻译。

## 边界

机器翻译不保证每句准确。OPUS 为支持逐 token 取消使用 greedy 解码，适合快速粗译；复杂文本可选择高质量引擎并核对。本轮修复和样例检查不替代通用翻译质量评测。

本轮没有重启桌面控制或重新进行音频/录屏交互验收，也未在物理旧 CPU、全新 Windows 环境验收。安装器源码保护已验证，未生成或实装 Inno Setup 安装程序；交付物为便携离线包。

收尾：额外验证了旧部署没有运行时数据的清理边界；无遗留项目进程。清理重复部署和本轮临时文件至少 1,414,680,834 字节（约 1.32 GiB），保留当前交付、旧 ZIP、原模型和三份旧模型 manifest。
